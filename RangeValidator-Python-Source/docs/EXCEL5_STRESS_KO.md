# Excel-5 대용량 COM 검증

합성 C 헤더와 합성 통합 문서로 실제 Windows Excel을 검증했다. 입력 파일과 이전 단계의 결과는 그대로 보존했다. 혼합 시트 순서는 고정 시드로 섞었다. 각 규모에 A형과 B형이 같은 수로 들어 있고, 500개 변수 구역 4개, 1,000개 변수 구역 2개, 제외 시트 6개를 포함했다. Name과 범위 열 위치, 중간 빈 행, 반복 변수명, 병합 제목·헤더·셀, 빈 결과 수식, 범위 헤더 누락 및 먼 서식 셀을 함께 검증했다.

|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 120 | 213,009 | 7,499 | 7,481 | 18 | 0 | 0 | 0 | 0 |
| 200 | 310,640 | 9,923 | 9,896 | 27 | 0 | 0 | 0 | 0 |
| 300 | 428,592 | 13,073 | 13,031 | 42 | 0 | 0 | 0 | 0 |

독립 정답은 워크북 생성 시점에 따로 저장했다. 비교기는 파일·시트·Name 주소를 키로 삼아 원래 값, Range/Scope 주소, 양식, 구역, 판정 및 수정 가능 여부를 검사했다. 미확정은 범위 헤더가 없어 예상한 결과이며 자동 수정 후보가 없음을 확인했다. 제외 시트 본문은 열지 않았다.

COM 초기화에는 DispatchEx와 설정이 포함된다. Open은 그 초기화를 뺀 값이다. A/B 인식과 추출은 같은 순회에서 수행되므로 합산했다. C/H 연결과 범위 판정은 각각 내부 함수 시간이며, 결과와 수정 후보를 만드는 비용은 전체 비교 시간에 포함된다. 저장할 후보를 고르는 시간은 Writer JSON에 따로 있다. 단계 시간은 일부 중첩되므로 행 합계가 전체 시간과 같지 않다. COM 호출 수는 관측한 API 진입 및 보조 함수 횟수로 기록했다. 모든 COM 속성 접근의 RPC 총수는 측정하지 않았다.

50ms 간격으로 샘플링한 Python과 시험 Excel의 최대 작업 집합은 120개 시트에서 76.3·133.9 MiB, 200개에서 87.4·136.7 MiB, 300개에서 102.1·139.5 MiB였다. 이 수치는 관측 최고값이다. 300개 시트의 병합 확인은 21.295초로 본문 32.249초의 약 66%였다. 본문 읽기가 가장 큰 비용이었다.

8개 조합에서 3,220셀 모두 기존 Writer의 `SAVED_VERIFIED` 및 별도 COM 재읽기 검사를 통과했다. 기존값, 기대값, 저장 후 실제값, 주소와 수식 여부는 `synthetic/write_*_cells.json`에 있다. 원본 SHA-256은 모두 일치했고, 수정본은 `_fixed.xlsx`로만 생성했다. 범위 헤더가 없는 표는 수정 후보에서 제외됐다. 병합 비앵커와 빈 문자열을 반환하는 수식은 REVIEW와 보호 상태를 유지했다. Writer 재열기에는 새 COM 인스턴스 시작이 포함된다. 검증·정리는 검증 시작부터 해당 인스턴스 정리 완료까지다. 독립 COM 재읽기 뒤 대상 값의 대조 시간과 파일 크기, 메모리는 각 사례 JSON에 따로 있다.

## 한도와 확인한 결함

- 기본 Reader 예산은 시트 512개, 통합 문서의 관측 데이터 직사각형 250,000셀, 값 및 수식 텍스트 16,000,000자다. 열 상한은 256이다. Find가 경계를 확인하면 Excel의 행 주소까지 사용하며 셀 예산은 계속 적용된다. Find에 실패한 행의 UsedRange 대체 상한은 200,000행이다. 대체 읽기는 최소 4,096행과 64열을 탐색하되, 데이터가 없는 패딩을 내용 크기로 집계하지 않는다.
- COM은 약 131,072셀 단위로 Value2와 Formula를 읽고 CountA가 0인 블록은 건너뛴다. 이전에는 연속 빈 블록 두 개 뒤의 값이 누락됐다. 관측한 끝까지 검사하고 반환 배열 크기가 요청과 다르면 해당 시트를 부분 읽기로 기록하도록 수정했다.
- 257열 내용은 이전 코드에서 조용히 잘렸다. 이제 상한 초과를 읽기 오류로 남긴다. 실제 파일에서 `1. Wide_limit`의 A1:IW20 및 합성 구역 Global(Input)을 영향 범위로 기록했다. 같은 파일 `2. Long_table`의 변수 3,100개는 정확히 추출했다. 값이 없는 먼 XFD 서식 셀은 데이터 끝으로 잡히지 않았다.
- 기존에 COM 경로에서 적용되지 않던 셀 예산을 실제 데이터 직사각형에 적용했다. 텍스트·시트 한도 및 병합 확인 한도 초과도 명시적으로 보고한다. 병합 가능성이 있는 200,000셀 초과 범위는 병합 상태를 모르는 채 수정 후보로 사용하지 않는다. 읽기 오류에 시트, 시도 범위, 한도 사유를 보존한다.
- 파일 단위 오류에 COM 내부 HRESULT를 함께 보존하도록 수정했다. 예외 메시지로 회사 파일 오류의 원인이나 DRM 상태를 추정하지 않았다.

실제 COM에서 A393217에 값이 있는 희소 시트도 확인했다. 기본 250,000셀 예산에서는 해당 시트만 부분 처리됐고, 같은 파일의 정상 시트는 읽혔다. 시험 호출에만 500,000셀 예산을 넘겨 다시 읽었을 때 두 빈 블록 뒤의 A393217 값이 확인됐다. 제품 기본값은 250,000셀이다. 기록은 `sparse_budget.json`에 있다.

## 오류 격리와 시험 범위

| 상황 | 검증 방식 | 관측 결과 |
|---|---|---|
| 누락 경로, 손상 XLSX, 배타 공유 잠금 | 실제 COM | Workbooks.Open 실패. 외부 `0x80020009`, 내부 `0x800A03EC`. 실패 파일에 비교 결과가 생성되지 않았으며 뒤의 정상 파일은 완료 |
| 미지원 CSV | 실제 실행의 입력 검증 | `path` 단계에서 거부. COM HRESULT 없음 |
| 열·셀 예산 초과 | 실제 COM | 해당 시트 부분 처리, 정상 시트의 분석 유지 |
| 권한 거부, Open·Value2 오류, 짧은 배열, UsedRange 대체 상한 | 모의 COM | 단계·파일·시트·HRESULT·시도 범위를 검사하고 정상 형제 파일·시트의 처리 확인 |
| SaveAs 실패, 재열기 실패, 검증값 불일치, 정리 실패 | 모의 COM | 실패 또는 미검증 상태 기록, 오류가 난 셀을 검증 성공으로 집계하지 않음 |
| 이미 열려 있는 합성 문서 | 실제 별도 Excel 인스턴스와 STA | 읽기·쓰기·재열기 중 기존 합성 문서의 창, 경로, 문서 수, 셀 값, 저장 상태 유지. 시험이 소유한 인스턴스만 정상 정리 |

오류가 예상된 시험의 `SUCCESS`는 오류 격리와 상태 기록이 기대대로 작동했다는 뜻이다. 첫 배타 잠금 실행은 결과를 남기기 전에 종료됐고, 단독 재실행에서 위의 오류 코드와 정상 후속 처리를 확인했다. 첫 동일 STA 감시 시험에서는 감시 프록시가 연결 해제됐다. 이 실패는 `ownership_same_apartment.json`에 남겼으며, 별도 STA에서 다시 검증한 결과는 `ownership.json`에 있다. 실제 사용자가 열어 둔 문서와 회사 ACL·DRM 동작은 미검증이다. 실제 Excel에서 SaveAs·재열기·검증·정리의 고장 자체를 강제로 만들지는 않았으며 해당 고장 경로는 모의 COM으로 검사했다.

## 회귀

- 실제 COM으로 Excel-4 독립 정답 7,793개를 다시 대조했다. A형 3,853개와 B형 3,935개, 총 7,788개가 정확했다. 미확정 5개와 잘못된 연결 0건이 유지됐다. 기존 혼합 120개 시트의 7,260개 및 A형 105개 시트의 주소 15,981쌍도 일치했다. 기록은 `baseline.json`에 있다.
- 오류·한도·Writer 상태를 다룬 모의 시험 19개가 통과했다. 이 중 7개가 이번에 추가한 시험이다. 개별 결과는 `mock_errors.json`에 있다.
- 전체 회귀 220개 중 204개가 통과했다. 선택 테스트 16개는 기본 회귀에서 건너뛰었으며 실패와 오류는 0개였다. 실제 COM 결과는 별도로 수행한 스트레스 실행에서 확인했다.

## 재실행

프로젝트 폴더에서 Excel과 pywin32가 연결된 Windows Python으로 `python -B tools/diagnose_excel5.py ../excel5-recheck mixed`를 실행한다. 구분 인수로 `writer`, `edges`, `isolation`, `baseline`을 선택하거나 `--case`로 한 사례를 실행할 수 있다. 실제 실행 결과는 `../excel5-diagnostic`에 있고, 워크북과 독립 정답은 `synthetic`에 있다.

## Excel-6 검증 우선순위

1. 병합이 거의 없는 300개 시트와 병합이 많은 300개 시트를 같은 변수 수로 대조하고, 병합 위치와 범위 질의 횟수별 시간·메모리를 측정한다.
2. 250,000셀 및 병합 확인 한도 바로 아래·같음·바로 위에서 파일과 시트 상태, 오류 범위, 수정 차단을 비교한다. 큰 공백과 먼 서식 셀을 교차 배치해 재현성을 높인다.
3. 저장할 파일 수와 셀 수를 독립적으로 늘려 SaveAs, Excel 시작·정리, 셀별 검증 비용을 분리한다. 원본 해시와 수정 대상 셀별 재열기 검증을 합격 기준으로 유지한다.
