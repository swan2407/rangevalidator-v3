# RangeValidator Python V3 — Windows 사용자 안내

## 실행

ZIP을 새 폴더에 전부 풀고 `RangeValidator-Python.exe`를 실행하세요.
EXE와 `_internal` 폴더를 함께 보관해야 합니다. Python/pip/MSYS2는 필요하지
않습니다. Excel COM 읽기/수정에는 설치·인증된 Microsoft Excel과 회사가
승인한 DRM 클라이언트·계정·접근 정책이 별도로 필요합니다.

1. **파일 등록**에서 Common Parameter XLSX, 여러 C 헤더, 여러 상세설계서를
   등록합니다. C 파일 인코딩을 UTF-8 또는 CP949로 명시합니다.
2. **비교 실행**을 누릅니다. 일반 XLSX는 openpyxl, 형식/접근 실패는 조건부로
   COM을 사용합니다. 접근 실패가 곧 DRM이라는 뜻은 아닙니다.
3. **비교 결과**에서 MATCH/MISMATCH/REVIEW/SKIP을 확인합니다. 여러 페이지의
   결과를 필터로 탐색할 수 있습니다. 안전한 MISMATCH의 체크 칸만 선택할 수
   있습니다. REVIEW와 일반 정수 멤버는 자동 수정할 수 없습니다.
4. **수정 및 저장**에서 선택 목록과 출력 폴더를 확인하고 저장을 승인합니다.
   매번 새로운 `RangeValidator_...` 하위 폴더를 생성하며 원본을 덮어쓰지 않습니다.
5. 결과 폴더에는 수정된 상세설계서와 `RangeValidator_Report.xlsx`를 제공합니다.
   여러 하위 디렉터리 입력은 상대 디렉터리를 유지합니다. 보고서는
   Summary/Changes/Review/Errors/Results로 구성됩니다.
6. 실패 시 **진단 로그**를 확인하세요. COM 실패 시 자동 표시됩니다. 기본 로그는
   회사 경로·셀 값·원문 예외를 담지 않습니다. 로그 복사/파일 저장은 선택입니다.

## 결과 상태

- MATCH: 확인된 비트필드 표현 가능 범위와 일치.
- MISMATCH: 확인된 비트필드 범위와 불일치. 안전 조건을 충족해야 선택 가능.
- REVIEW: 선언·표·범위·입력 상태 등을 확정하지 못함. 자동 수정 금지.
- SKIP: 일반 정수 멤버·자리 표시자 등 분석 제외.
- VERIFIED: **일반 XLSX의 지정된 보존 검사 통과**. DRM 보호 유지 인증이 아닙니다.
- DRM_CONFIRM_REQUIRED: **회사 DRM 보호 유지/추가 보존 확인 필요**. 완료로 간주하지 마세요.
- 저장 REVIEW/실패: 출력 파일이 남더라도 검증 완료본으로 사용하지 마세요.

범위는 C 비트필드가 표현할 수 있는 값이며, 요구사항 유효값이나 도달 가능한
실행 값이 아닙니다. plain int signedness는 추정하지 않습니다. 지원 프로파일은
V1과 같은 32비트 int/명시적 signed·unsigned 및 정확한 uint 별칭입니다.

## 지원 경계

Common은 File/Name/Type/Value 표에서 변수 선언을 읽습니다. Value에서 타입을
추론하지 않습니다. Macro/Calibration/Struct/Enum 절은 변수 선언으로 사용하지
않습니다. 배열·const/volatile·한 단계 포인터는 Common 선언 규칙 안에서 지원합니다.
A는 Name/Type/Range 및 확인된 절, B는 Input/Output/Property/Name/Data type/Scope를
탐지합니다. 수식/병합 데이터 셀은 REVIEW입니다. 안전한 가로 병합 헤더만 지원합니다.

조건부 전처리, 일반 typedef 체인, 중첩 구조체/표현식, 복잡한 선언, 함수/로컬/반환
값 흐름은 지원하지 않으며 REVIEW로 남깁니다. AST/CFG/Alias Analysis는 없습니다.

저장 검증은 값·수식·셀 서식·행열 크기·병합·숨김 시트·이미지 데이터/위치 등을
대조합니다. Excel의 테마/색상/글꼴 XML 정규화는 원본과 재개봉 저장본의 실제
적용 서식으로 비교합니다. 미지원 객체(ActiveX/매크로/피벗/외부 링크/알 수 없는
패키지 요소/조건부 서식·데이터 유효성 등)는 보수적으로 저장을 막을 수 있습니다.
차트 XML 변화나 보존 불일치는 REVIEW로 처리합니다. 임의 OOXML 전체의 바이트
동일성이나 모든 Excel 객체 보존을 보증하지 않습니다.

COM 전용 문서는 Find 영역 안의 값·수식·서식·시트/그림 메타데이터를 메모리에서
대조합니다. 그림 원본 바이트와 데이터 영역 밖 전체 서식은 확인할 수 없으므로
일반 XLSX와 동일한 보존 인증을 부여하지 않습니다. 평문 임시 XLSX는 만들지 않습니다.

실제 회사 DRM 파일의 읽기/정책 거부/출력 보호 유지는 개발 환경에서 검증하지
않았습니다. 회사 승인 환경에서 별도 검증해야 합니다. SaveAs 성공만으로 DRM
보호 유지를 판단하지 마세요. 프로그램은 DRM 해제·암호 탐색·보안 정책 변경을
수행하지 않습니다. COM이 정책 대화상자나 서버 정지로 반환하지 않는 경우에는
강제 종료하지 않으며, GUI는 정리가 끝난 뒤 종료합니다. 관리된 테스트 입력을 사용하세요.

## 라이선스 및 배포

`licenses/`에 CPython(배포에 포함된 Microsoft 런타임 조건 포함), Tcl/Tk,
openpyxl/et_xmlfile, pywin32, Pillow, PyInstaller와 관련 고지를 포함합니다.
타사 저작권/라이선스 고지를 제거하지 마세요. 체크섬은 `SHA256SUMS.txt`에 있습니다.
깨끗한 회사 PC/EDR/보안 승인/DRM 정책별 검증은 별도 작업입니다.

## DRM 읽기 오류의 진단 로그 확인 (최신 진단 배포)

오른쪽 아래 **진단 로그 보기** 버튼을 누르면 별도 진단창이 열립니다.
읽기 실패 시에는 이 창과 진단 로그 탭이 자동으로 표시됩니다. 창을 크게
늘리고 **글자 크게**를 누르면 화면 촬영이 편합니다. 가로·세로 스크롤과
복사를 지원하며, 기본적으로 경로·파일명·셀 값·원문 예외는 생략합니다.

실행 ID, Reader, DispatchEx/Open/Find/Value2/Close/Quit, 성공·실패,
HRESULT·Win32 코드, 실패 API와 마지막 성공 단계를 확인하세요. 실패 로그는
입력 목록을 변경해도 현재 앱 안에서 유지됩니다. 재시작 후 자동 복원은
하지 않으므로 필요한 경우 복사하거나 선택적으로 로그를 저장하세요.

일반 Reader 실패 후 COM이 성공하는 경우 두 결과가 모두 남습니다.
읽기 실패 자체를 DRM 거부로 단정하지 마세요. 실제 회사 DRM 파일은 별도
승인 환경에서 확인해야 하며, 이 진단 배포에서는 전체/Writer/보고서 회귀를
실행하지 않았습니다. 관련 검증: `DIAGNOSTIC_AUDIT.md`.

## DRM 대량 읽기: 파일별 실행 상태

비교 결과 상단의 **파일별 실행 상태**에서 입력 번호, Reader, 읽기 성공/실패,
실패 API/코드/예외 타입, 시트·검색 단계, 실제 변수 비교 수행, 추출 수,
MATCH/MISMATCH/REVIEW/SKIP 수를 확인하세요. `ERROR` 필터는 읽기·실행 실패
파일을 보여 주며, 이 오류는 비트필드 REVIEW 건수에 포함하지 않습니다.
읽기가 성공했어도 변수 행을 얻지 못하면 NO_VARIABLES/비교 미실행으로 표시합니다.

입력 상태는 다음과 같이 구분합니다.

- STABLE: SHA-256·크기·수정시간 재확인 일치.
- CONTENT_CHANGED: SHA-256 또는 크기의 변경 근거가 있음. DRM 문서의 논리적
  내용이 바뀌었다고 추정하는 의미가 아니라, 입력 바이트/크기 증거가 달라진 상태입니다.
- METADATA_CHANGED: SHA-256·크기는 같고 수정시간만 다름.
- STATE_UNAVAILABLE: 전후 상태를 조회할 수 없거나 해시 중 상태가 불안정함.

입력 상태 문제는 파일·변수·구조체·멤버·셀·범위 등 비교 당시 근거를 지우지
않습니다. 다만 현재 파일에 대한 안전한 수정 근거가 아니므로 저장 후보를
차단합니다. 기존 세션 전체 입력 검사도 유지하여, 다른 입력에 상태 문제가
있을 때도 저장은 막습니다. 단순 Reader 실패와 입력 상태 문제는 별개입니다.

진단 로그에는 파일명 대신 `detail #번호`/시트 번호와 first_row/last_row/
first_column/last_column 검색 단계가 남습니다. SHA/크기/mtime 변경 여부는
True/False로, 조회 불가·해당 없음은 None으로 기록합니다. 실제 해시나 셀 내용은
기본 로그에 남기지 않습니다.

읽기 전용 Find/셀 값/수식/병합 속성 호출에서 0x80010001 또는 0x8001010A가
발생하면 동일 STA에서 최대 3회(추가 대기 합계 0.35초)만 시도합니다.
Open/DispatchEx/저장/Close/Quit는 이 재시도 대상이 아닙니다. 연결 끊김·기타
오류는 자동 무한 재접속하지 않습니다. Close/Quit 실패는 별도로 표시합니다.

실제 회사 DRM·UNC 상태 변화 원인과 Find 실패의 환경 원인은 개발 환경에서
미검증입니다. Open 성공을 전체 읽기 성공으로 판단하지 마세요.
